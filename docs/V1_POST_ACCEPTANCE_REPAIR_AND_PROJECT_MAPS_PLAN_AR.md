# OpenGeo v1.0 — خطة ما بعد اختبارات القبول ومتصفح خرائط المشروع

> **تاريخ التأسيس:** 21 أغسطس 2026  
> **المصدر:** نتائج `AE-V1-01…07` الفعلية وملاحظات تجربة المستخدم  
> **الهدف:** إغلاق العيوب المؤثرة على سلامة v1.0، ثم بناء إدارة خرائط المشروع دون خلطها بسجل الطبقات المتجهية داخل الخريطة الواحدة  
> **قاعدة المنتج:** Live Sync خدمة خفية ودائمة. أما Record فهو وضع كتابة مفاتيح مستقل لكل Map composition.

---

## 1. الحكم التنفيذي

نتائج القبول الأساسية إيجابية: `AE-V1-01` و`02` و`04` و`06` ناجحة بالكامل، بينما كشفت التجربة ثلاثة عقود تحتاج تصحيحًا قبل قرار `GO`:

1. كانت هوية آخر Map composition تبقى في العميل بعد مغادرتها، فتُرسل محاولة GeoJSON إلى Controller قديم.
2. كان Record حالة عامة للوحة، ولم يكن يثبت مفتاح البداية لحظة تشغيله.
3. كان Clear يمسح علامات المعاينة فقط رغم أن موقعه وتسميته يوحيان بمسح حركة الخريطة.

أُصلحت هذه العقود في المصدر، وأضيفت لها اختبارات آلية. أما **متصفح خرائط المشروع، اسم الخريطة، وصور البطاقات** فهي قدرة منتج مستقلة وليست تصحيحًا تجميليًا لسجل Layers. يجب تنفيذها على مراحل لأنها تضيف عقد Host جديدًا، metadata جديدة، وحالة UI جديدة.

## 2. قاموس النطاق حتى لا تختلط المفاهيم

| المفهوم | النطاق | مصدر الحقيقة | ما يديره |
|---|---|---|---|
| Map composition | مشروع AE كامل | Composition metadata + Controller ownership | خريطة مستقلة بكاميرا ومزوّد ومقاس وخصائص |
| Layers | Map composition واحدة | `FeatureRegistry` + Host feature comments | البلدان وGeoJSON المرسومة داخل الخريطة الحالية |
| Project Maps | مشروع AE كامل | مسح Host محدود للكومبوزيشنات المملوكة لـOpenGeo | فتح الخريطة، عرض الاسم والصورة والحالة |
| Live Sync | اللوحة كلها، دائم | `AESyncEngine` | مزامنة الكاميرا بلا زر تشغيل/إيقاف |
| Record | لكل Map composition | سجل runtime مفهرس بـ`compId` | تحويل حركة اللوحة إلى مفاتيح عند CTI |
| Add Key | أمر لحظي | AE Controller properties | إضافة/تحديث مفتاح واحد عند الزمن الحالي |
| Clear | الخريطة الحالية | أمر Host مكتوب النوع | حذف مفاتيح الكاميرا مع حفظ قيمة الكادر الحالي |

لا يجوز أن تتحول نافذة Project Maps إلى نسخة ثانية من Layers، ولا أن يعتمد فتح خريطة على اسم الكومبوزيشن؛ الهوية التقنية هي `documentId` و`compId`، والاسم للعرض فقط.

## 4. المرحلة R1 — تصحيح هوية الكومبوزيشن وGeoJSON

### العقد المطلوب

- إذا أعاد `camera.getActive` حالة بلا `compId`، تصبح جلسة العميل بلا Map composition فورًا.
- يُنشر `sync:compChanged { oldId, newId: null }` مرة واحدة فقط.
- لا يُستدعى `metadata.get` بمعرّف قديم أو فارغ.
- عناصر `Preview only` تبقى في `FeatureRegistry`، بينما عناصر Host الخاصة بالكومبوزيشن المغادَر لا تتسرب.
- رفع GeoJSON في هذه الحالة ينتهي عند Canvas وLayers، ولا يستدعي `vector.import`.

### التحقق

- [x] اختبار آلي لفصل الهوية القديمة.
- [x] اختبار آلي لحفظ preview drafts بلا قراءة metadata قديمة.
- [ ] `AE-V1-03R` داخل After Effects.

## 5. المرحلة R2 — Record وAdd Key كآلة حالات لكل خريطة

### آلة الحالة

```text
OFF --click Record--> ADDING_INITIAL_KEY --success--> RECORDING
                                  |--failure-------> OFF
RECORDING --click Record--------------------------> OFF
switch A -> B: اعرض حالة B فقط
switch B -> A: استعد حالة A من سجل الجلسة
panel restart: كل الخرائط تبدأ OFF لأمان المشروع
```

### القواعد

- Live Sync يبقى عاملًا في جميع الحالات؛ لا زر له ولا preference لتعطيله.
- تشغيل Record بلا Map composition يُرفض قبل أي Bridge call.
- لقطة الكاميرا و`compId` تُثبتان قبل الاستدعاء غير المتزامن.
- المفتاح الأول يستخدم `comp.time` في Host، لا زمنًا يرسله العميل.
- إذا تغير الكومبوزيشن أثناء إضافة المفتاح، لا تُبنى معاينة المسار في الخريطة الجديدة.
- لا تُحفظ حالة Record في metadata أو المشروع؛ استعادتها بعد إعادة التشغيل قد تكتب مفاتيح بلا قصد.

### التحقق

- [x] اختبار استقلال A/B.
- [x] اختبار إضافة المفتاح الأول.
- [x] اختبار rollback عند فشل إضافة المفتاح.
- [ ] `AE-V1-05R-A` و`AE-V1-05R-B`.
- [ ] تدقيق يدوي لعدد Undo عند عشر حركات متتالية في وضع Record.

## 6. المرحلة R3 — تعريف Clear تعريفًا صريحًا وآمنًا

### السلوك المعتمد داخل Map composition

1. فتح مودال OpenGeo، لا نافذة JavaScript أصلية.
2. عرض النطاق بدقة: مفاتيح `Latitude` و`Longitude` و`Zoom` فقط.
3. قراءة القيم المقيمة عند CTI قبل حذف أي مفتاح.
4. حذف المفاتيح تنازليًا داخل `withUndoGroup` واحدة.
5. تثبيت قيم CTI كقيم static حتى لا يقفز الكادر.
6. إيقاف Record لهذه الخريطة.
7. إعادة بناء preview ثابت واحد.

لا يحذف Clear:

- طبقات البلدان أو GeoJSON.
- Controller Null.
- Finalized tiles.
- Map composition أو أصول المشروع.

عند عدم وجود Map composition، يمسح Clear مساعدات المعاينة المؤقتة فقط ولا ينفذ أمر Host.

### التحقق

- [x] حذف تنازلي مختبر.
- [x] حفظ قيم CTI مختبر.
- [x] `keyframe.clear` عقد Bridge مكتوب النوع.
- [ ] `AE-V1-05R-C` مع Undo فعلي.

## 7. المرحلة R4 — تبسيط Toast وهوية Compact

### مواصفات الواجهة

- ارتفاع أدنى `30px`، أيقونة `15px`، حواف `4px`.
- خلفية من متغيرات ثيم OpenGeo وحدّ محايد واحد.
- ممنوع `border-left` الملون للأنواع.
- اللون الدلالي محصور في الأيقونة وبدرجة هادئة.
- لا blur ثقيل، ولا ظل كبير، ولا تغطية للشريط العلوي أو أدوات البحث.
- النص يصف الإجراء والنتيجة، ولا يعرض stack أو مسار ملف محلي حساس.

## 8. المرحلة P1 — اسم الخريطة في New Composition

### نموذج البيانات

إضافة حقل اختياري:

```json
{
  "displayName": "North Africa Overview"
}
```

القواعد:

- طول من 1 إلى 80 محرفًا بعد trim.
- يُنظف من محارف التحكم، ولا يستخدم في اسم ملف أو مسار.
- إذا كان فارغًا، يولد `OpenGeo Map 1`, `OpenGeo Map 2`… داخل المشروع.
- يبقى `documentId` الهوية الثابتة؛ تغيير الاسم لا يغير ownership أو مجلد الأصول.
- اسم كومبوزيشن AE يكون نسخة آمنة من `displayName` مع suffix قصير عند التعارض.
- metadata القديمة بلا `displayName` تفتح بلا migration مدمرة وتستنتج اسم العرض من اسم الكومبوزيشن.

### تغييرات الواجهة

- حقل `Map name` هو أول عنصر في New Composition modal.
- زر New Comp يتحول إلى زر أيقوني أخضر يحوي `plus` فقط.
- `title="Create a new OpenGeo map"` و`aria-label` إلزاميان.
- لا يُحذف المودال؛ الزر المضغوط يفتحه فقط.

### اختبارات القبول

- [ ] اسم عربي ولاتيني وطويل وفارغ.
- [ ] خريطتان بالاسم نفسه لا تتصادمان.
- [ ] reopen يحفظ الاسم.
- [ ] rename لاحق لا يكسر Finalize أو FeatureRegistry.

## 9. المرحلة P2 — متصفح Project Maps

### الهدف

زر مستقل يفتح مودالًا يعرض كل خرائط OpenGeo الموجودة في مشروع AE الحالي، سواء كانت الكومبوزيشن مفتوحة في Viewer أم لا. لا يعتمد على `activeItem` وحده.

### عقد Host المقترح

`project.listOpenGeoMaps` يعيد بحد أقصى 200 سجل:

```json
{
  "maps": [{
    "compId": 192,
    "documentId": "map_...",
    "displayName": "North Africa Overview",
    "width": 1920,
    "height": 1080,
    "providerId": "esri",
    "camera": { "lat": 28.0, "lng": 2.0, "zoom": 5.8 },
    "isFinalized": true,
    "featureCount": 3,
    "hasController": true
  }]
}
```

`project.openOpenGeoMap { compId, documentId }` يتحقق من التطابق والملكية ثم يجعل الكومبوزيشن Active ويفتحها في Viewer. لا يقبل اسمًا كهوية.

### اكتشاف الخرائط

- مسح `CompItem` فقط.
- إثبات الملكية من metadata الصحيحة وController ذي comment المعتمد.
- عدم تعديل أي عنصر أثناء list.
- تجاهل الكومبوزيشنات التالفة مع إرجاع `skippedCount` للتشخيص، لا إسقاط العملية كلها.
- ترتيب ثابت: Active أولًا، ثم الاسم، ثم `compId`.

### الصور المصغرة

لا ننفذ Render Queue أو `saveFrameToPng` لكل بطاقة عند فتح المودال؛ ذلك سيجمد AE ويضيف ملفات ومخاطر صلاحيات. التصميم المعتمد:

1. يرسم العميل Thumbnail من `camera + providerId + aspect ratio`.
2. يستخدم tile cache الحالي إن وجد.
3. عند ضعف الشبكة يستخدم Offline Vector thumbnail.
4. cache مصغر مفهرس بـ`documentId + metadataRevision` وحد أقصى 40 صورة.
5. placeholder فوري، ثم ترقية الصورة latest-wins؛ البطاقة لا تنتظر الشبكة لتصبح قابلة للفتح.

### واجهة المودال

- Grid مضغوط يتكيف من عمود إلى ثلاثة.
- نسبة الصورة تساوي نسبة الكومبوزيشن، مع letterbox محايد.
- الاسم هو النص الأساسي؛ الأبعاد والمزوّد وحالة Finalized معلومات ثانوية.
- حالة الخريطة النشطة واضحة بلا لون صارخ.
- Click/Enter يفتح؛ Escape يغلق؛ focus trap/restore من `DialogManager` أو Modal base موحد.
- Empty state يوجّه إلى زر `+`.

### حالات الخطأ

- مشروع غير محفوظ: العرض والفتح مسموحان؛ لا حاجة لمسار ملفات.
- Controller ناقص: بطاقة `Needs repair` ولا تُفتح بصمت كخريطة سليمة.
- metadata قديمة: تعرض باسم مستنتج وتُرقى فقط عند حفظ لاحق آمن.
- حذف كومبوزيشن بعد list: open يعيد `MAP_NOT_FOUND` وتُزال البطاقة بعد refresh.
- تبديل المشروع أثناء تحميل الصور: generation يلغي كل النتائج القديمة.

## 11. قرار الإصدار

### الحاجب حاليًا

- اعتماد `AE-V1-03R` و`AE-V1-05R-A/B/C` و`AE-V1-07R` على المصدر الجديد.
- إعادة `verify:release` وتوليد artifact manifest بعد آخر تعديل.

### قرار نطاق Project Maps

قرر مالك المنتج في 21 أغسطس 2026 أن **Project Maps شرط أساسي لـv1.0**. لذلك الحالة الحالية `NO-GO مؤقت` رغم نجاح التنفيذ الآلي، ولا يتحول القرار إلى `GO` حتى اجتياز اختبارات خريطة واحدة وعدة خرائط، الأسماء العربية والمتكررة، فتح البطاقة، وضع الشبكة الضعيفة، وController التالف. عملية list تبقى read-only ولا تنشئ Undo أو تعدل المشروع.
