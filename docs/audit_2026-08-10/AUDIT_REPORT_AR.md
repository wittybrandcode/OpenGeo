# تقرير التدقيق الفني والأمني — OpenGeo

**تاريخ التدقيق:** 2026-08-10  
**النطاق:** `OpenGeo/`، بما في ذلك CEP client، ExtendScript host، البناء والتغليف، المزوّدون الخارجيون، والوثائق.  
**نوع التدقيق:** مراجعة ساكنة، فحوصات بناء، تحقق من اتساق الحزم والمراجع، وفحص HTTP غير موثق المفاتيح لمزوّدي الخرائط.  
**خارج النطاق:** تشغيل Adobe After Effects نفسه؛ لذلك لا تمثل النتائج ضماناً لاختبارات AE المرئية أو أداء الـ GPU.

## الحكم التنفيذي

لا ينبغي توزيع OpenGeo في حالته الحالية. التطبيق المصدر قابل للفحص، لكن مسار النشر ينتج `dist/` غير مكتمل، وبالتالي ستفشل إضافة ZXP الناتجة. توجد أيضاً دالة مفقودة في مسار تفاعل حقيقي، ومنافذ لحقن ExtendScript، واستعمال `eval` داخل المضيف.

التصنيف الإجمالي: **غير صالح للإصدار (Release Blocked)** حتى إغلاق عناصر P0 الواردة في خطة الإصلاح المرافقة.

## منهجية الفحص

1. جرد بنية المشروع ونقاط الدخول: `manifest.xml` و`client/index.html` و`host/index.jsx`.
2. التحقق من أن كل مورد محلي مشار إليه في صفحة العميل موجود في المصدر وفي `dist/`.
3. تشغيل `npm run build`، و`npx rollup -c`، وسكربت التغليف القديم.
4. فحص صياغة JavaScript في كود المشروع وفحص صلاحية XML.
5. مطابقة واجهات `opengeo*` المستدعاة من العميل مع الدوال المعرفة في ExtendScript.
6. مراجعة مسارات `evalScript` و`eval` وصلاحيات CEP والوصول إلى نظام الملفات.
7. تجربة HTTP لمربعات الخرائط عند `z/x/y = 2/2/2`، دون مفاتيح API.
8. تشغيل `npm audit --omit=dev`.

## النتائج التفصيلية

### OG-001 — `dist` لا يحتوي تطبيق العميل الفعلي

**الدليل**

- `scripts/build.js` يعتمد قائمة نسخ يدوية قديمة؛ يشير إلى `main.js` و`TileEngine.js` و`ViewportController.js` وغيرها، وهذه لم تعد ضمن المصدر.
- السكربت يطبع تحذيراً للمفقودات ثم ينتهي بنجاح (`exit 0`).
- `client/index.html` الحالي يحمل 35 script تقريباً. بعد تشغيل سكربت التغليف، كان 34 مرجعاً محلياً من `dist/client/index.html` غير موجود.
- `scripts/zxp.js` يغلّف `dist/` نفسه، لذا لا توجد طبقة حماية لاحقة تمنع توزيع الحزمة الناقصة.
- بقايا ملفات الجيل القديم داخل `dist` تخفي الخطأ ولا تعالج اعتماديات الصفحة الجديدة.

**الأثر**

سيظهر panel فارغ أو سيتوقف عند تحميل أول script مفقود في أي تثبيت مبني من `dist` أو ZXP.

**الإصلاح المطلوب**

استبدال قائمة النسخ ببناء نظيف من staging ينسخ شجرة `client/` و`host/` و`CSXS/` كاملة مع قائمة استبعاد صريحة. يجب أن يتحقق البناء من جميع روابط HTML وأن يفشل عند أول مورد مفقود. لا يحق لسكربت التغليف الاستمرار مع warnings.

### OG-002 — استدعاء method غير موجود

**الدليل**

في `client/js/app.js`، مستمع `overlay:changed` يستدعي:

```js
this._queueAutoExport();
```

ولا توجد method بهذا الاسم في class `App`.

**الأثر**

تعديل GeoJSON أو marker أو طبقة قد يؤدي إلى `TypeError` ويمنع دورة التصدير التلقائي اللاحقة. هذا مسار مستخدم فعلي وليس مجرد كود ميت.

**الإصلاح المطلوب**

إما تعريف wrapper وحيد يستدعي `this.syncManager.queueAutoExport()`، أو استبدال الاستدعاء مباشرة. يضاف اختبار يحاكي `overlay:changed` ويثبت وجود تصدير واحد فقط دون loop.

### OG-003 — بناء أوامر ExtendScript بسلاسل غير مؤمنة

**الدليل**

`client/js/ae/SpatialPin.js` يبني أمراً بهذه الصيغة:

```js
'opengeoAddSpatialPin("' + compId + '", ... "' + name + '", ...)'
```

`name` يأتي من `prompt`، ولا يهرب quotation marks أو backslashes. توجد أنماط مشابهة لـ `compId` و`layerId` و`blendMode` في bridge وmetadata وsync.

**الأثر**

اسم marker مصمم خصيصاً يمكنه كسر string وإلحاق أوامر ExtendScript. لأن الامتداد يعمل داخل After Effects وبصلاحيات واسعة، فهذا خطر أمني عالٍ.

**الإصلاح المطلوب**

إنشاء API وحيد في `AEBridge` يفرض serialisation لكل argument. تعامل string كـ `JSON.stringify(String(value))`، والأرقام كقيم finite validated فقط. يمنع استعمال interpolation اليدوي في جميع call sites. يضاف security regression test بأسماء تتضمن `"`, `'`, `\\`, CR/LF، وUnicode.

### OG-004 — `eval` لتحليل بيانات JSON في ExtendScript

**الدليل**

`host/modules/compBuilder.jsx` و`spatialPinHost.jsx` و`vectorHost.jsx` تنفذ `eval('(' + raw + ')')` على payload أو محتوى ملف.

**الأثر**

أي ملف مؤقت أو payload يمكن العبث به يتحول من بيانات إلى كود قابل للتنفيذ في AE. الاستعمال غير لازم لأن المشروع يستعمل `JSON.parse` في مواضع أخرى.

**الإصلاح المطلوب**

استبدال `eval` بـ`JSON.parse` حصراً، ثم التحقق من schema والحدود العددية وحجم المصفوفات قبل إنشاء طبقات AE. أخفق بأمان برسالة يمكن للعميل عرضها.

### OG-005 — مزود Stadia Terrain غير صالح بالإعداد الحالي

**الدليل**

- `config.js` يعرض `stamenTerrain` دون `requiresKey`.
- اختبار GET مباشر للرابط المعرف في config أعاد HTTP 401.
- لا يوجد حقل Stadia API key في الواجهة.

**الأثر**

المستخدم يختار مصدراً معطلاً ويواجه طلبات فاشلة ومؤشرات تحميل بلا نتيجة.

**الإصلاح المطلوب**

إزالة المزوّد من القائمة إلى أن تتوفر سياسة اعتماد واضحة، أو إضافة `requiresKey: true` وحقل مفتاح آمن وحالة "مفتاح مطلوب" قبل إرسال أي request. يجب ألا تخرج `{key}` غير مستبدلة في URL.

### OG-006 — امتيازات قوية وإعداد debug مشحونان

**الدليل**

الـ manifest يفعّل `--enable-nodejs` و`--mixed-context` و`--allow-file-access-from-files`، وملف `.debug` موجود ضمن ما ينسخه سكربت التغليف.

**الأثر**

تمتزج DOM ومصادر الشبكة مع Node وfilesystem. أي XSS مستقبلي أو بيانات غير موثوقة قد يكتسب وصولاً محلياً أوسع بكثير من اللازم. كما يبقى debugging مفعلاً في التوزيع.

**الإصلاح المطلوب**

فصل manifest التطوير عن manifest الإنتاج، واستبعاد `.debug` من كل artefact منشور. راجع كل CEF flag واحتفظ فقط بما تثبت الحاجة إليه. لأن Node مطلوب حالياً، يجب أن يصاحبه validation صارم لكل مدخلات الشبكة/الملفات وحدود واضحة لمسارات الكتابة.

### OG-007 وOG-008 — مسار TypeScript/Rollup غير موصول بالتشغيل

**الدليل**

- `npm run build` يشغّل `tsc` فقط وينتج ملفات تحت `client/js/engine/dist`.
- `npx rollup -c` يفشل لأن إعداد Rollup ESM بينما package معلنة CommonJS.
- runtime يحمل `client/js/engine/OpenGeoEngine.js` الكلاسيكي، وليس bundle الناتج من TypeScript.
- توجد نسخ JavaScript مولدة داخل `engine/src`، ونسخ أخرى في `engine/dist`، إضافة إلى implementation القديم.

**الأثر**

يمكن أن يصلح المطور TypeScript دون أن يتغير المنتج الفعلي؛ وتبقى السلوكيات متباعدة بمرور الوقت.

**الإصلاح المطلوب**

قرار معماري صريح: اعتماد TypeScript+Rollup كالمحرك الوحيد أو حذف المسار غير المستخدم. بعد القرار، اجعل build واحداً قابلاً لإعادة الإنتاج ويملك artifact واحداً محملاً من `index.html`.

### OG-009 — افتراض مسار تثبيت ثابت

**الدليل**

توجد fallbacks إلى `C:/Program Files (x86)/Common Files/Adobe/CEP/extensions/OpenGeo`، وكذلك إلى `C:/Users/Public` و`C:/Temp`.

**الأثر**

يفشل التطبيق أو يكتب في موقع غير مقصود عند التثبيت في `%APPDATA%`، أو في جهاز ذي قرص مختلف، أو عندما لا يملك المستخدم صلاحية الكتابة داخل Program Files.

**الإصلاح المطلوب**

استخدم `CSInterface.getSystemPath(SystemPath.EXTENSION)` للقراءة و`SystemPath.USER_DATA` للـ cache/jobs/logs. لا تستخدم مسار ثابتاً إلا كحل فشل مؤقت بعد تنبيه المستخدم.

### OG-010 إلى OG-012 — جودة الإصدار والوثائق

**الدليل**

- لا يوجد test runner أو اختبارات تلقائية أو إعداد lint أو CI.
- README يصف `main.js` و`AEInterface.js` القديمين، بينما نقطة الدخول الحالية `app.js` و`core/AEBridge.js`.
- الإصدارات: package/manifest = 1.0.0، config = 1.1.0، وmetadata = 2.0.0.
- يوجد حقل Google API key بلا provider Google فعلي، و`SettingsPanel` يبحث عن عناصر DOM غير موجودة لكنه يتسامح معها بصمت.

**الإصلاح المطلوب**

إنشاء contract للنسخة، توثيق حديث، CI إلزامي، وإما ربط عناصر الواجهة بوظائف حقيقية أو حذفها.

## قيود الثقة

لم يتم تشغيل After Effects من هذه البيئة، لذا يجب تنفيذ smoke tests وstress tests داخل الإصدارات المستهدفة من AE قبل اعتماد النسخة. لا تقلل هذه القيود من خطورة OG-001 إلى OG-006؛ فهي مثبتة بالقراءة والتنفيذ المحلي/الشبكي المباشر.

## القرار

**لا توقّع ولا تنشر ZXP قبل إكمال P0 وإعادة تشغيل بوابة القبول كاملة.** راجع `WORLD_CLASS_REPAIR_PLAN_AR.md` للتنفيذ التفصيلي.
