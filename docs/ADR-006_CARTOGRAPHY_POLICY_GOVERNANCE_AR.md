# ADR-006 — حوكمة سياسة الخرائط والحدود المتنازع عليها

**الحالة:** مقبول ومنفذ  
**التاريخ:** 14 أغسطس 2026  
**الإصدار:** 1.0.0  
**ملف السياسة الملزم:** `scripts/vector-data-sources/CARTOGRAPHY_POLICY.json`

## السياق

تتلقى OpenGeo بيانات جغرافية من مصادر متعددة، وقد تختلف هذه المصادر في تمثيل المناطق المتنازع عليها. ترك القرار داخل كود البناء أو واجهة البحث يجعل تغيير المصدر قادرًا على تعديل الخريطة بصمت، ويمنع معرفة القاعدة التي أنتجت هندسة Composition قديمة.

## القرار

1. تُحكم كل استثناءات الحدود بملف سياسة ذي إصدار، ولا تُدفن إحداثيات الفصل أو قواعد الدمج في كود البناء.
2. المرجع الابتدائي الافتراضي لأي نزاع جديد هو مرجع خرائطي أو جغرافي صادر عن الأمم المتحدة بعد مراجعته وتثبيت مصدره وترخيصه وبصمته.
3. يملك مالك المنتج حق اعتماد استثناء صريح يسبق المرجع الافتراضي، بشرط تسجيل معرف القرار ومبرره والدول المتأثرة والمصادر والبصمات ورفع إصدار السياسة.
4. لا توجد «سياسة عالمية» تعيد تشكيل جميع النزاعات دفعة واحدة. يُراجع كل ملف نزاع مستقلًا، وتكون إضافته بلا أثر تشغيلي حتى يتحول إلى profile نشط.
5. تسجل Composition إصدار سياسة الخرائط وإصدار حزمة البيانات ومعرفات profiles الفعالة وبصمة ملف السياسة.

## القرار المحمي الحالي: MAR/ESH

- تبقى هندسة المغرب `MAR` وهندسة الصحراء الغربية `ESH` كما اعتمدها مالك المنتج قبل هذا القرار.
- profile الحالي هو `western-sahara-separated-v1` وحالته `active-locked`.
- البناء يقارن SHA-256 للهندسة الناتجة لكل من `MAR` و`ESH` بالبصمتين المعتمدتين، ويفشل قبل نشر البيانات إذا تغيرت أي نقطة.
- لا يحق لتطوير فلسطين أو أي نزاع آخر تعديل profile هذا أو تحديث بصماته ضمنيًا.

## فلسطين والنزاعات المستقبلية

سُجل `palestine-boundary-review-v1` كعمل مخطط بلا أثر runtime. تفعيله مستقبلًا يتطلب:

1. تحديد نطاق الهويات والهندسات المتأثرة.
2. تثبيت مرجع الأمم المتحدة المستخدم محليًا مع provenance والترخيص وSHA-256.
3. توثيق أي اختلاف يختاره مالك المنتج عن المرجع الافتراضي.
4. إضافة اختبارات هندسة ذهبية وبصمات مستقلة.
5. رفع إصدار السياسة وحزمة البيانات، ثم مراجعة بصرية منفصلة داخل AE.

## ترتيب القرار

1. استثناء صريح ومُصدّر من مالك المنتج.
2. مرجع أممي مراجع ومثبت.
3. المصدر المحلي canonical المثبت عندما لا يوجد profile نزاع نشط.

هذا الترتيب سياسة عرض للمنتج، وليس حكمًا قانونيًا أو ادعاءً بأن ملف البيانات يحسم الوضع السياسي.

## ضمانات التنفيذ

- `build-land-border-data.js` يقرأ السياسة ويتحقق من schema والمصادر والبصمات.
- ملف `client/assets/data/vectors/cartography-policy.json` هو نسخة runtime مولدة، وليس مصدر القرار.
- `CartographyPolicy` يقرأ النسخة المحلية ويقدم stamp ثابتًا إلى `MetadataManager`.
- metadata القديمة تبقى قابلة للتحميل؛ metadata الجديدة تحتفظ بختم السياسة لغايات التتبع وإعادة الإنتاج.
- ZXP لا يُبنى في هذه المرحلة وفق قرار المنتج السابق.

## الرجوع

إذا فشل تحميل السياسة أو تغيرت هندسة محمية، يتوقف بناء البيانات ولا تُستبدل ملفات runtime المعتمدة. الرجوع يكون باستعادة ملف السياسة ومصادره المثبتة، لا بتجاوز فحص البصمة.

## أدلة القبول

- إعادة بناء 258 محيطًا محليًا بنجاح.
- تطابق بصمتي MAR وESH مع baseline المحمي.
- اختبارات السياسة وmetadata ضمن `npm test` ناجحة.
- نجاح build وتدقيق package دون إنشاء ZXP.
