# تقرير التدقيق الشامل لمشروع OpenGeo

**تاريخ التدقيق:** 9 أكتوبر 2026  
**النطاق:** مصدر CEP، مضيف ExtendScript، خط أنابيب البلاطات، البيانات المتجهة، الأمن، الأداء، الاختبارات، وسلامة إصدار الحزمة.  
**حالة المصدر عند التدقيق:** شجرة عمل غير نظيفة؛ لم يُسجَّل خط أساس جديد ولم تُقبَل التغييرات تلقائياً.

## الخلاصة التنفيذية

المشروع سليم وظيفياً بحسب الاختبارات الآلية: اجتازت حزمة الجودة كاملةً 15 مجموعة اختبار، واجتاز اختبار الحزمة. كما اجتازت بوابات الأمن، التوافق، الأحداث، الأداء، الاعتمادات، والبيانات.

تم إصلاح سبب فواصل بلاطات الخريطة برمجياً. لم يعد OpenGeo يكبّر الصورة الجغرافية كاملةً لإخفاء الفاصل؛ بل يضيف بكسل حافة مكرراً داخل أصل الـ MegaTile، ثم يضعه في After Effects بمقياس محتوى دقيق. لا يزال القبول البصري داخل After Effects مطلوباً، لأن التدقيق الآلي لا يستطيع تشغيل عارض AE على لقطات 400–800%.

**قرار الجاهزية:**

| المجال | الحالة | القرار |
| --- | --- | --- |
| الوظائف والاختبارات الآلية | ناجح | مقبول |
| الأمن والاعتمادات | ناجح | مقبول |
| الأداء والتوافق | ناجح | مقبول |

## إصلاح فواصل البلاطات

### ما تم تغييره

1. ينتج `MegaTileArtifactStore` أصلاً أكبر ببكسل واحد من كل طرف، لكنه يحفظ حجم المحتوى المنطقي منفصلاً.
2. ينسخ العامل وبديل Canvas صفوف وأعمدة الحواف إلى هذا الإطار؛ لذلك لا توجد شفافية خارج texture أثناء أخذ العينات الثنائية.
3. يرسل `MegaTileStitcher` حقلي `contentPixelSize` و`gutterPixels` إلى المضيف.
4. يضبط المضيف Anchor Point إلى مقدار الحافة، ويحافظ على:

   ```javascript
   Scale = worldTileSize / contentPixelSize
   blendingMode = BlendingMode.NORMAL
   samplingQuality = LayerSamplingQuality.BILINEAR
   ```

5. أضيف اختبار `TB.11` لعقد الحافة والمقاس، إلى جانب اختبارات المسار السابقة.

### أثر الإصلاح

- لا يوجد `ALPHA_ADD`، لذلك لا يظهر توهج أبيض في منطقة التماس.
- لا يوجد تمديد لصورة الخريطة نفسها، لذلك لا تنزاح الطرق أو حواف التضاريس.
- تظل كاميرا 3D و`collapseTransformation` والبنية الحالية مدعومة.
- الأصول القديمة ليست قابلة للترقية سحرياً؛ إعادة الاستيراد ضرورية كي تحمل صورة المصدر الحافة الجديدة.

### بروتوكول القبول اليدوي

1. افتح مشروع AE محفوظاً وانشئ Preview أو Finalize جديداً.
2. شغّل حركة تبدأ خلال أول ثانيتين، مع Pitch بين `0°` و`45°`.
3. راقب حدود الـ MegaTiles عند `100%` و`400%` و`800%`.
4. اعتبر الاختبار ناجحاً فقط إن لم يظهر فراغ أسود أو شريط أبيض أو ازدواج واضح للمعالم.
5. إن ظهرت مشكلة، احتفظ بلقطة وإطار الزمن وZoom وPitch واسم مزوّد البلاطات قبل أي تعديل جديد.

## خارطة الإصلاح المقترحة

### المرحلة 0: اعتماد الإصلاح والإصدار

1. نفّذ قبولاً بصرياً لإصلاح الـ MegaTile.
2. راجع التغييرات الـ32 في خط الأساس، ثم حدّث `BASELINE_MANIFEST.json` بعد قبولها فقط.
3. أعد إنشاء manifest الإصدار بعد تقرير التوافق الأخير، ثم شغّل `npm run artifact:verify`.
4. نفّذ `npm run verify:release` في شجرة عمل نظيفة قبل تغليف ZXP.

### المرحلة 1: تقليل المخاطر بأقل تغيير

1. أضف اختبار قبول AE مصوراً لفواصل البلاطات.
2. عدّل تشخيص `artifact-manifest.js` ليذكر الحقول المخالفة مثل `inputs.compatibilityReportSha256`.
3. أنشئ owner وSLA لكل بوابة: baseline، artifact، security، compatibility، performance.

### المرحلة 2: التفكيك المعماري

1. ابدأ بـ`GeoDataRepository` و`OpenGeoEngine` لأنهما يمزجان أربعة مجالات.
2. انقل حسابات Mercator والتغطية والتحقق إلى `client/js/core/geometry/` بوحدات خالصة واختبارات وحدات.
3. اجعل وحدات CEP وAE adapters رقيقة مع façade يحافظ على واجهاتها الحالية.
4. فكك `vectorHost.jsx` و`compositionTransaction.jsx` على مراحل صغيرة، مع `npm run test:all` و`npm run verify:package` بعد كل مرحلة.

## حدود هذا التقرير

- لا يساوي نجاح الاختبارات الآلية قبولاً بصرياً داخل After Effects؛ لذلك لم تُعلن مشكلة الفواصل «مقبولة نهائياً» قبل اختبار AE اليدوي.
- اختلاف خط الأساس وartifact manifest لوحظ في شجرة عمل تحمل تعديلات مسبقة، لذا لا ينسب التقرير تلك التغييرات لشخص أو تعديل بعينه.
- لم يتم تسجيل baseline أو artifact manifest جديدين عمداً؛ فهذه عمليات اعتماد تغييرات ويجب أن تتبع مراجعة بشرية.
