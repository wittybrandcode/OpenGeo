# ميزانيات أداء OpenGeo وحدود الاستهلاك

**الإصدار:** 1.0.0  
**التاريخ:** 14 أغسطس 2026  
**العقد الآلي:** `config/performance-budgets.json`  
**المدقق:** `scripts/performance-audit.js`  
**آخر نتيجة:** ناجحة

## الهدف

تحويل قرارات الأداء من أرقام موزعة داخل الملفات إلى عقد fail-closed. لا يقيس هذا العقد سرعة After Effects نظريًا من Node؛ بل يحمي الحدود التي تمنع تضخم الذاكرة والطلبات والطبقات، ويشغّل benchmark قابلًا للتكرار على بيانات Vector Preview المحلية. تبقى أزمنة Bridge وHost الحقيقية ضمن اختبار AE لأنها تعتمد المشروع والجهاز وحالة After Effects.

## ميزانية Vector Preview

| المقياس | الحد الأقصى | آخر قياس |
|---|---:|---:|
| Parse p95 لكل chunk | 50ms | 2.48ms |
| حجم chunk واحد | 2,097,152 bytes | 1,202,194 bytes |
| النقاط المرئية في أسوأ نافذة عينة | 400,000 | 306,695 |
| chunks المرئية في أسوأ نافذة عينة | 24 | 20 |

القياس الحالي يغطي 89 chunk محليًا على Node 22.18.0/Windows x64. أرقام الزمن تشخيصية وتعاد في كل release gate؛ حدود الحجم والنقاط حتمية بالنسبة إلى حزمة البيانات نفسها.

## آلية المنع

يشغّل `npm run audit:performance` خطوتين:

1. يقرأ الحدود الفعلية من ملفات التشغيل ويقارنها بالعقد. تغيير أي رقم داخل الكود وحده يفشل البناء، ويجبر المراجع على تعديل policy صراحة.
2. يقيس parse وحجم/تغطية chunks ثم يفشل إذا تجاوزت إحدى الميزانيات.

تشغّل `verify:release` هذا التدقيق تلقائيًا وتنتج `release/performance-report.json`. كما تدخل بصمة ملف الميزانية نفسه في `artifact-manifest.json`، لذلك لا يمكن تبديل السياسة بعد التحقق من artifact دون كشفه.

## ما لا يدعيه القياس الآلي

- لا يمثل زمن `evalScript` الحقيقي داخل AE.
- لا يمثل زمن فك الصور أو الاستيراد تحت ضغط مشروع حقيقي.
- لا يثبت استقرار heap بعد دورات طويلة داخل CEP.
- لا يستبدل قياس drag/zoom أو Finalize على Host المستهدف.

لهذه الأسباب تبقى اختبارات الأداء اليدوية في M9 مطلوبة، بينما يعتبر عقد الحدود البرمجي مكتملًا.

## أوامر التحقق

```powershell
npm run benchmark:preview
npm run audit:performance
npm test
npm run verify:release
npm run artifact:verify
```

## قاعدة تعديل الميزانية

لا تُرفع أي قيمة لإسكات failure. يجب توثيق dataset/scenario الذي تسبب في التجاوز، وقياس الأثر داخل AE، ثم تعديل policy والكود والاختبار والخطة في تغيير واحد. خفض الميزانية مسموح إذا أثبتت القياسات أن الهامش الجديد واقعي على الحد الأدنى المدعوم.
