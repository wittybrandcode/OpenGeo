> **النطاق:** منطق العميل `client/js/**`، مضيف After Effects في `host/**`، عقود البيانات، وسلسلة الاختبار والبناء `scripts/**`

## 2. المنهجية ونطاق الإثبات

استُخدمت المناهج التالية بصورة عملية، لا كشعارات توثيقية:

1. **ISO/IEC 25010** لتقييم الملاءمة الوظيفية، الموثوقية، الكفاءة، الأمن، التوافق، وقابلية الصيانة.
2. **SoC / SRP / SOLID** لرصد كائنات God Object وتسرب UI إلى الأعمال وتعدد مصادر الحقيقة.
3. **تحليل تدفق البيانات والأحداث** من DOM/EventBus إلى Session ثم Bridge وHost، مع تتبع `compId`, `documentId`, generation وrevision.
4. **تحليل linearizability والسباقات** للعمليات البطيئة: تبديل الكومبوزيشن، الاستعادة، الرسم، الحذف، Live Sync وFinalize.
5. **STRIDE مُكيّف لبيئة CEP ذات Node** عند حدود الشبكة وfilesystem وpayload files و`evalScript` وmetadata.
6. **FMEA** لتقديم العيوب بحسب الشدة واحتمال الحدوث وصعوبة الاكتشاف.
7. **DRY / Dead-code reachability** بمقارنة ملفات runtime مع `index.html` والعمال الديناميكيين والمستهلكين الفعليين.
8. **Release reproducibility** عبر clean stage، syntax checks، SBOM، package verification وSHA-256 artifact manifest.

## 4. تقييم معماري حسب الوحدة

### 4.1 الحالة ومصدر الحقيقة

`MapSession` هو المصدر المركزي لهوية المستند والكاميرا والمزوّد والحجم وعمليات generation وسجل الخصائص. `StateHydrator` يطبّق transaction مع rollback، بينما `CompositionController` يرفض أي نتيجة load متأخرة. هذا البناء صحي ولا توجد كتابة بديلة معروفة تتجاوز Session في مسار الاستعادة.

التحسين المهم في هذا التدقيق هو أن `FeatureRegistry.replaceAll` صار all-or-nothing، وأن metadata لا يمكنها تجاوز ميزانية آمنة أو حذف سجل الخصائص أثناء Finalize.

### 4.2 الأحداث

`EventBus` بسيط ومتزامن عمدًا، لكنه يلتقط رفض المستمعات غير المتزامنة ويرسله إلى قناة الخطأ. كتالوج الأحداث يغطي كل الاستعمالات الحرفية. أضيف رفض المستمع غير الدالة وتنظيف bucket الفارغ. لا توجد دورة أحداث مثبتة أو event toggle لـLive Sync؛ الخدمة تبقى background دائمًا كما يقتضي قرار المنتج.

### 4.3 الجسر CEP ↔ ExtendScript

يمر العميل عبر `AEBridge.invoke` فقط. كل رسالة تحمل protocol version وrequest ID وcommand وتُطابق مع envelope الاستجابة. لا يوجد استدعاء `_evalScript` خارج الجسر. Dispatcher في Host ذو جدول أوامر صريح، والبيانات الثقيلة تمر بملفات مؤقتة محدودة بدل تضمينها في النص.

أُغلق آخر اتساع مهم لحدود الثقة: Host يتحقق الآن أن ملف payload يقع في مجلد OpenGeo المُدار. كما صار commit النهائي يستخدم مدقق metadata نفسه بدل الكتابة المباشرة.

### 4.4 Undo ومعاملات Host

كل mutation رئيسي يستخدم `withUndoGroup` ذي `finally` واحد: build، vector import، visibility، delete، pin، keyframe وFinalize prepare/commit/rollback. استعلامات الحالة والمسح لا تفتح Undo، وتحديث الكاميرا الحي لا يولّد Undo لكل حركة. لا يظهر nesting داخلي غير مقصود في المسارات الحالية.

### 4.5 Live Sync والكاميرا والبلاطات

Live Sync خدمة خلفية دائمة. تدفق الكاميرا يستخدم revision acknowledgment وsingle-flight polling، ويمنع echo والعودة إلى موضع قديم. تخطيط البلاطات موحّد بين Preview وFinalize، ومحدد بميزانيات للذاكرة والتزامن والمسار الزمني. القياسات الآلية الحالية ضمن الحدود بوضوح.

### 4.6 Finalize

Finalize هو أقوى جزء transactionally: prepare مخفي، تحقق من العدد والهوية، commit مرئي، reconciliation عند timeout، rollback قبل commit، وتنظيف قديم بعد activation فقط. أضيف في هذا التدقيق عزل سجل الخصائص وانتظار vector work، وإدخال metadata عبر المدقق المركزي. لا يوجد success زائف معروف في المصدر الحالي.

### 4.7 المتجهات وGeoJSON

مسار البحث هو المصدر الوحيد لرسم حدود الدول المحلية عالية الدقة. GeoJSON يمر عبر validation وحدود للحجم والعدد والإحداثيات ثم الإسقاط والرسم. `FeatureManager` يملك الآن معاملة الاستيراد لجميع المداخل، بينما `FeatureRegistry` يملك descriptors و`FeatureOverlayLayer` المعاينة وHost يملك طبقات AE وController Null.

سياسة `MAR`/`ESH` والحزمة المحلية لم تُغيّر في هذا التدقيق، وحمايتها الهندسية ما تزال ناجحة.

### 4.8 UI ودورة الحياة

المودالات والتنبيهات من نظام OpenGeo وليست browser dialogs أصلية. المستمعات القابلة للإزالة و`dispose` متوفرة في الوحدات ذات دورة الحياة. أزيل إعداد محلي غير عامل بدل إبقائه كواجهة وهمية. لا يوجد ملف runtime غير قابل للوصول؛ `stitcherWorker.js` يُحمّل ديناميكيًا من `MegaTileStitcher`.

### 4.9 البناء وسلسلة التوريد

المسار الرسمي الوحيد هو `release/stage`. الحزمة لا تضم `node_modules` ولا docs ولا مصادر البناء الكبيرة. npm runtime dependencies = صفر؛ عشر مكونات Turf موجودة للبناء فقط ومثبتة في lockfile/SBOM. لم تُبنَ ZXP لأن قرار المنتج الحالي يؤجل التغليف النهائي ولا يجعله شرطًا لإغلاق منطق الإضافة.

## 6. القيود والمخاطر المتبقية

هذه ليست عيوبًا مثبتة مفتوحة، لكنها حدود يجب توثيقها قبل الإصدار:

1. **اختبار AE الحقيقي:** لا يمكن لمحاكاة Node إثبات عدد Undo Steps أو سلوك Viewer والطبقات عند تبديل الكومبوزيشن لحظيًا.
2. **فقد ملف GeoJSON المُدار أو نقل المشروع إلى جهاز آخر:** طبقات AE لا تُحذف؛ تظهر الخاصية `AE only` وتتعطل معاينة المصدر إلى أن يُعاد استيراده. هذا قيد v1 مقبول ومعلن.
3. **اختبار انقطاع شبكة فعلي:** أُجّل سابقًا بسبب قيود بيئة العمل. العقود والـtimeouts والـabort مختبرة آليًا، لكن الاختبار الواقعي يبقى مستحسنًا قبل الإطلاق العام.
4. **مصفوفة إصدارات AE:** العقد يعلن 18.4–24.99، لكن ينبغي smoke test على أقدم وأحدث إصدارين سيُدعمان تجاريًا إن كانا متاحين.
5. **ZXP والتوقيع:** خارج نطاق إغلاق منطق v1 حاليًا بقرار المنتج، ويجب تنفيذه كمرحلة تغليف منفصلة بعد قرار `GO`.

## 7. قرار الإصدار

### القرار الحالي: `CONDITIONAL GO`

- **آليًا:** `GO` — جميع البوابات ناجحة ولا توجد P0/P1 معروفة مفتوحة.
- **وظيفيًا داخل AE:** ينتظر الاختبارات القصيرة `AE-V1-01` إلى `AE-V1-07`.
- **إذا نجحت الاختبارات اليدوية:** يتحول القرار مباشرة إلى `GO v1.0` دون مرحلة refactor أخرى.
- **إذا فشل اختبار:** يُعاد فتح finding واحد محدد فقط؛ لا يُعاد فتح الخطة المعمارية كاملة بلا دليل جديد.
